Goals

N1Close O1: publish Mesh IQ flag precision

real datafailure cases of existing methodscarryover · sample frozenneeds human reviewers

Why. 77 of 307 segments are flagged, but no one has yet measured how many flags are real.

Starting point. Blinded 54-segment sample and key-free packet (mesh-review-sample), protocol frozen in mesh-review-protocol.md.

Deliverable. Returned reviewer labels, scored by bin/mesh_review_score.py as written in the protocol.

Done when. Flag precision and the clean-segment defect rate are committed with 95% intervals. If no review comes back by Nov 21, publish that as the status and keep the rate unknown.

N2One exact-volume surface result, scored blind

Grand Prize bottleneckheld-out validationtools ready · campaign not started

Why. This is the only goal that moves the bottleneck sentence. Everything else improves trust in the evidence around it.

Starting point. The frozen PHerc0139 sheetness reference campaign (sheetness-campaign.md), the blind TIFXYZ scorer scroliq-segmentation-validate (segmentation-validation.md) and the target-freeze gate (target-freeze-gate.md).

Deliverable. Pre-register a transfer to one exact prize-eligible volume: volume ID, probe boxes, engine bytes, truth source and decision rule. Commit the salted truth commitment before predictions exist, produce TIFXYZ predictions, and score them.

Done when. One scored run is committed with its verdict, whether that verdict is pass or fail, with bidirectional coverage, topology gates and per-region failures. A failed transfer is a result, not a reason to change the rule.

N3First blind evaluation of a community model

gets usedheld-out validationharness readyneeds a model owner

Why. scroliq-eval is infrastructure until it has evaluated a real model somebody else built.

Starting point. Contracts, overlap blocking, bootstrap CIs and the two-trust-domain design (model-evaluation.md). Zero published evaluations.

Deliverable. One public surface or ink model evaluated on a declared held-out region, with model card, checkpoint hash and the overlap check, all committed.

Done when. The result envelope with CIs and failed regions is committed and linked from the progress board. Ask the model owner before publishing anything about their model.

N4Fiber IQ part 2: CT support, and test the fallback–gap pattern

real dataopen problem: fiber connectivitycensus done

Why. The 136-fiber census found every one of the 388 gap candidates inside fibers with fallback-interpolated spans. That co-occurrence becomes actionable for annotators only if it is tested, and fiber geometry means little until it is checked against CT.

Starting point. fiber-corpus-census: 136 fibers, 502 / 5,503 fallback spans, 388 gaps, 519 sharp turns.

Deliverable. (a) A pre-registered span-level test: are gap candidates over-represented in fallback spans compared with native spans of the same fibers? (b) A CT-support check on an exact, declared PHercParis4 volume root, with a positive control: a fiber shifted off the sheet must be flagged.

Done when. (a) is decided by its frozen rule, and (b) catches its positive control without flagging the unshifted calibration fibers. If no exact CT binding can be established, (b) stays unknown with the reason.

open problem: spiral fittingcarryover · evaluator readyneeds a GPU fit run

Ground rules (unchanged)

  • Every number traces to a command and a committed artifact. README, docs and artifact READMEs change together.
  • Every checker has a positive control and reports unverified when it inspected nothing.
  • Pre-register, then log every deviation. Failed gates are published.
  • No readability claims from the scan-health score. Exact-volume, fail-closed Grand Prize matching.
  • Dated data is frozen data. Upstream filing and releases need explicit maintainer approval.
